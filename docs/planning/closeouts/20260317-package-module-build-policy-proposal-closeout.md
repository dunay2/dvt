# Closeout: Package Module Build Policy Proposal

## Think-First

### Problem summary

The repo has already started converging app and package build configuration,
but it still lacks a written canonical policy for package module format,
tsconfig families, metadata shape, and migration order.

### Root cause

Refactoring slices started reducing duplication before a target package model
was explicitly written down. Without that policy, cleanup work risks becoming a
series of local optimizations instead of a coherent convergence plan.

### Constraints and invariants

- `AGENTS.md` requires think-first before edits and explicit closeout evidence.
- `docs/guides/ai-work-protocol.md` requires options considered before writing
  implementation or planning material.
- `docs/guides/testing-and-ci-capabilities.md` defines the canonical docs and
  validation commands that should still pass after documentation changes.
- `ADR-0018` requires package boundary ownership to stay explicit, so the
  policy must not normalize hidden cross-package shortcuts.

### Options considered

1. Keep the policy as ad hoc closeout knowledge only.
   Rejected: operationally weak and hard to review.
2. Save the policy as a planning proposal first, then migrate toward it.
   Selected: right level of authority for a target-state model that still needs
   review and incremental adoption.
3. Publish it immediately as an accepted ADR.
   Rejected: too early before team review and before current exceptions are
   explicitly classified.

Libraries evaluated:

- None added. This is a governance and repository policy document task.

### Selected option and rationale

Write the improved policy as a planning proposal under
`docs/planning/proposals/` and pair it with a closeout that records why the
proposal was added now.

### Rejected alternatives

- Leave the policy only in chat or commit messages.
  Rejected because it is not discoverable or governable.
