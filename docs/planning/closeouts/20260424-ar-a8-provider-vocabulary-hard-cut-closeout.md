# AR-A8 Provider Vocabulary Hard-Cut Closeout

## Think-First Analysis

Problem summary:

Active runtime contracts still treat `conductor` as a valid provider even though
the production runtime is Temporal-only. The mismatch appears in contract
types, validation schemas, engine test stubs, API target-adapter vocabulary, and
active adapter documentation.

Root cause:

The repository kept future-provider vocabulary inside active runtime surfaces.
That made portability look executable before a Conductor adapter, conformance
suite, and production composition path existed. This is an architecture truth
problem, not a missing implementation detail.

Constraints and invariants:

- ADR-0014 makes provider adapters run-driven and behind ports.
- ADR-0012 makes engine-side plan integrity the authoritative admission gate.
- Active production truth is Temporal-only until another provider has real code
  and conformance coverage.
- No compatibility alias, legacy stub, or fake provider success path is allowed.
- API composition remains a PEP/composition surface; provider runtime details
  stay behind provider-adapter factories.

Options considered:

- Keep `conductor` in types and fail at runtime. Rejected because it preserves
  paper portability and lets callers select a provider that cannot execute.
- Move `conductor` into a deprecated or reference-only active doc. Rejected
  because the repository has a hard-cut posture for this slice.
- Narrow the active provider vocabulary to implemented providers only. Chosen
  because it makes type-checking, validation, docs, and runtime composition
  agree.

Selected option and rationale:

Narrow active runtime provider vocabulary to Temporal. Remove fake engine stubs,
remove active Conductor adapter documentation, and add architecture tests that
fail if active runtime contracts expose Conductor again without a real adapter
and conformance suite.

Rejected alternatives:

- A compatibility migration period. Rejected by the active hard-cut direction.
- A new remote provider abstraction. Rejected as unrelated; `IProviderAdapter`
  already owns the hexagonal port.

## Pre-Implementation Brief

Mode: Full.

Scope:

- `@dvt/contracts` provider vocabulary, runtime schemas, validation tests, and
  architecture guard.
- `@dvt/engine` provider selection, in-memory adapter, removed stubs, and tests.
- `apps/api` runtime target-adapter vocabulary and provider-factory tests.
- Active docs, evidence, risk, and planning lane state.

Expected outcome:

Only `temporal` is an active runtime provider. Any production or contract path
that tries to use `conductor` fails at compile time or validation time.

Risks and mitigations:

- Broad type fallout from narrowing `EngineRunRef`: mitigate with TDD and
  package-level contract/engine/API validation.
- Historical docs references: mitigate by removing only active adapter surfaces
  and regenerating docs indexes.
- False-positive string guard: scope architecture tests to active runtime
  source paths, not archived context.

Out of scope:

- Implementing a Conductor adapter.
- Designing a future multi-provider contract line.
- Changing Temporal runtime execution semantics.

Validation plan:

- `pnpm --filter @dvt/contracts test`

Test coverage plan:

- Red architecture test that active contracts and runtime docs do not expose
  `conductor`.
- Validation test that `parseRunContext`, `parseRunExecutionContext`, and
  `parseEngineRunRef` reject `conductor`.
- Engine provider-selection tests that `ENGINE_PROVIDER=conductor` is invalid.
- API adapter-factory tests that registration cannot advertise Conductor.

Libraries evaluated:

None evaluated - no custom implementation or external dependency is needed.

## Fowler QA

Fowler QA is recorded in:

- `buzon/20260424-codex-fowler-provider-vocabulary-hard-cut-qa.md`

Findings applied:

- removed paper portability from active contracts and docs;
- replaced repeated provider literals with the shared
  `RUNTIME_PROVIDER_VALUES` source;
- deleted dead provider stubs instead of preserving compatibility aliases;
- moved provider vocabulary semantics into a local component guide with public
  API, invariants, transitions, consumers, and regression guard;
- added module-level owned-concern docblocks for changed boundary modules;
- expanded architecture coverage so active docs, capability matrices, event
  schemas, and composition surfaces must agree.
