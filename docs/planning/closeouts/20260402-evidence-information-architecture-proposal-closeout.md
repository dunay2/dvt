# Closeout: Evidence Information Architecture Proposal

## Think-First

### Problem summary

The repository has active evidence documents, but the `docs/evidence/` surface
does not yet distinguish blocking proof from supporting or contextual records.
The flat index makes retrieval, audit, and future automation harder than it
needs to be.

### Root cause

Evidence documents were standardized enough to accumulate under one directory,
but not enough to express class, lifecycle, or folder admission rules. The repo
therefore optimized for document creation before it defined a stable
information architecture for evidence as a governed surface.

### Constraints and invariants

- `AGENTS.md` requires governance-first startup, closeout evidence, and no
  hidden process drift.
- `docs/guides/ai-work-protocol.md` requires think-first and a closeout for
  planning-affecting work.
- `docs/planning/state/planning-control-tower.md` requires plan/proposal work
  to live under `docs/planning/proposals/` and stay linked to the execution
  workboard.
- `docs/DOCS_README.md` requires canonical landing pages and archive discipline.
- `docs/planning/status/governance-document-rule-inventory.md` classifies
  evidence as a supporting governance surface, not a replacement for reviews,
  closeouts, risks, or normative docs.
- `AGENTS.md` ARC policy currently expects evidence frontmatter with
  `evidence.tests`, so the proposal must not assume an immediate incompatible
  validator change.

### Options considered

1. Leave `docs/evidence/` flat and only improve titles.
   Rejected: fixes presentation but not governance or future automation.
2. Create a proposal that defines taxonomy, metadata, migration waves, and
   future enforcement without moving files yet.
   Selected: gives a governed target state without mixing policy design and
   content migration in one risky slice.
3. Immediately move files into new folders in the same pass.
   Rejected: too much link and validator risk before classification and
   compatibility rules are written down.

Libraries evaluated:

- None added. This is a repository governance and documentation structure task.

### Selected option and rationale

Create one planning proposal that defines the `docs/evidence/` target operating
model, then register that planning slice in the lane/workboard and close the
proposal-writing task with explicit validation evidence.

### Rejected alternatives

- Capture the target model only in chat or PR text.
  Rejected because it would not be canonical or reviewable.
