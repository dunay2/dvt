## Known Time Drivers

| Driver                  | Why it costs time                                                                                     | Current mitigation                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Governance startup      | Every task must identify the governing docs before analysis or edits.                                 | Keep the governing sources explicit in this log and in closeout.   |
| Command/query rail rule | Externally visible behavior cannot be added as an ad hoc web or API helper.                           | Confirm the owning rail before implementing.                       |
| Planning first          | Behavior, architecture, workflow, or contract changes require a local plan and rationale before code. | Keep remediation slices narrow and plan only the active slice.     |
| TDD                     | Each behavior change needs a failing test before implementation.                                      | Scope tests to the touched capability plus integration neighbors.  |
| Feature mechanization   | New plans and docs must declare allowed surfaces and symbols or the feature gate fails.               | Add plan surfaces while the slice is small.                        |
| Generated governance    | Docs/planning or governance-affecting changes require refresh commands.                               | Run refresh late, after code stabilizes.                           |
| Broad validation        | `pnpm verify:prepush` is required before claiming readiness and can be slow.                          | Run targeted checks first, then the broad gate once.               |
| Hook formatting         | Pre-commit may reformat staged files and repeat quick checks.                                         | Let the hook own final formatting; avoid separate Prettier passes. |
